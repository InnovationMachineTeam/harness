# Harness Console

В «Настройки → Guardrails» аудитор видит исполняемые правила, тестовое покрытие и все точки применения: код, runtime hooks, Husky, verification и CI. Понятные названия отображаются перед техническими ID. Правила, контрольные проверки и точки применения раскрываются по нажатию и показывают назначение, защищаемые ресурсы, действие, доказательства и порядок исправления. Вкладка позволяет выполнить проверку политики, тесты, обновить детерминированный отчёт и скачать текущий JSON-снимок.

Веб-консоль для управления задачами workflow, LangGraph-конвейером с ролями и рантаймами агентов (Claude Code, Codex CLI, ZCode, Cursor, Kimi Code, OpenCode).

Стек: **Bun**, **Next.js 15**, **React 19**, **Tailwind CSS v4**, **LangGraph.js**, **SQLite** и **React Flow**.

UI собран на внутреннем UIKit: примитивы - `src/uikit/components/UIKit/index.tsx` (импорт `@/uikit` через barrel `src/uikit/index.tsx`), все компоненты - в `src/uikit/components/<Имя>/`; layout-компоненты (`Page`/`PageHeader`/`NavBar`), кастомные контролы вместо нативных (`Select`, `confirmDialog`). Справочник - [`docs/ui-kit.md`](../../docs/ui-kit.md).

## Запуск

```bash
bash tooling/scripts/setup.sh   # проверка/установка системных зависимостей
                                 # (bun, node ≥ 22, openwiki) - с подтверждением
bun install            # из корня репозитория (workspaces)
bun run console        # dev-сервер → http://localhost:3000 (порт закреплён: next dev -p 3000)
# или из apps/console:
bun run dev
```

**Правило одного инстанса.** Консоль работает на порту **3000** и только там. Если порт занят - **не запускайте второй инстанс** (Next без явного порта молча перескочил бы на 3001/3002/…, и таких "потерянных" серверов легко накопить): сначала проверьте, какой процесс занимает порт (`lsof -i :3000 -sTCP:LISTEN`) - почти наверняка это уже запущенная консоль, пользуйтесь ей. Чужой или зависший процесс сначала остановите (`kill <pid>`), потом запускайте заново.

`setup.sh` показывает статус системы и ставит недостающее (macOS - Homebrew, Linux - официальные инсталлеры; правила - `AGENTS.md §10`), спрашивает пакетный менеджер глобальных npm-пакетов (Bun/NPM) и предлагает опциональные инструменты экономии токенов (Serena, qmd, CodeGraph, Graphify, RTK, Headroom). Если bun уже установлен, то же самое - командой `bun run setup` (полезные флаги: `--check` - только статус, `--yes` - без вопросов).

- `bun run console:build` - production-сборка (останавливайте dev-сервер: build и dev конфликтуют на каталоге `.next`);
- `bun run console:test` - unit-тесты (`bun test`);
- API: `/api/workflows`, `/api/roles`, `/api/roadmap`, `/api/workflow-runs`, `/api/stats`, `/api/runtimes`, `/api/mcp`, `/api/skills`, `/api/sessions`, `/api/processes`, `/api/workspaces`.

## Разделы консоли

Верхнее меню: Агент, Дизайн, Рантаймы, Знание, Мониторинг, Настройки; стартовая страница `/` и пункт меню "Агент" открывают раздел Агент. Внутри "Агента" - четыре вкладки: Агент, Задачи, Workflow, Роли (активная вкладка - параметр `?tab=`, прямые ссылки вида `/agent?tab=workflow`; старые маршруты `/workflows`, `/roles`, `/tasks` перенаправляют в раздел). Вкладки "Guardrails", "Рабочие папки", "Навыки", "MCP", "Плагины" входят в Настройки; прямые ссылки вида `/settings?tab=guardrails` открывают нужную вкладку.

- **Агент, вкладка Задачи** (`/agent?tab=tasks`) - доска задач workflow: карточка = прогон (папка артефактов `.agents/console/tasks/<run-id>/`); колонки "В работе", "Требует подтверждения" (паузы на плане и ручной приёмке), "Выполнены", "Остановлены" и **Backlog** (задачи из шагов планирования с оценками value/effort и лейблами спринтов); автообновление раз в 5 секунд. Кнопка **"Спринт"** открывает визард: шаг 1 - выбор задач чекбоксами, workflow на каждую и оценки value/effort; шаг 2 - параллельные корзины и ранжирование внутри корзины. Спринт помечает задачи лейблом `sprint:<id>`, двигает их по доске и исполняет служебным графом: worktrees (по worktree на задачу) - параллельные корзины (последовательность внутри) - закрытие - ретроспектива с lessons learned.
- **Агент, вкладка Workflow** (`/agent?tab=workflow`) - каталог, React Flow graph, YAML editor с ETag, partial run и список запусков. Узлы перетаскиваются мышью (позиция сохраняется в `ui`), соединяются и разрываются кликом по связи; при соединении артефакты источника автоматически записываются в outputs источника и inputs приёмника, а удаление чипа входа или выхода в редакторе шага разрывает соответствующую связь на канве. Сохранение отклоняется при несоединённых узлах и дублировании id; переименование workflow или шага распространяется на extends и связи. Кнопка **"Новый workflow"** создаёт пустой файл, **"Clone / extends"** копирует выбранный, фильтр по стадиям (start/end) и кнопка **"Создать из выбранных"** клонируют выбранный диапазон в новый workflow. Клик по узлу открывает модальный редактор с табами **Входной контроль / Исполнение / Выходной контроль / Общее**: роли выбираются чипами, DoR/DoD/AC и чек-лист тестов - списками, есть настройки попыток и ручных подтверждений; runtime candidates - чипами с перетаскиванием (CLI-рантаймы и провайдеры AI SDK "provider:<id>" через LangChain), пустой список наследует **"Runtime workflow"** (defaults.runtime, редактор - кнопка в тулбаре студии); справа - YAML шага. Страница run показывает шаги с ролями, статусами и чипами прогресса чеклистов (DoR, DoD+AC, счётчик возвратов); правая колонка - панель выбранного шага, отдельной страницы с журналом прогона нет. В верхней части панели - верхний сегмент **"Данные / Входной контроль / Исполнение / Выходной контроль"** (Данные активны по умолчанию; секции - по наличию в шаге); внутри "Данных" - вложенный сегмент **"Ошибки / Лог / Инструменты / Артефакты / Агенты / Статистика"** (по умолчанию Ошибки, если ошибки есть, иначе Лог). Вкладки секций показывают назначение секции, задание из workflow, чеклисты DoR/DoD/AC со статусами критериев по вердиктам контролей (возврат сбрасывает отметки "пройден"), пометки возвратов с проваленными критериями, промты подшагов и статистику (вызовы, токены, стоимость, время); AC в выходном контроле - с признаком "сгенерированы движком" или "из workflow". Шаги, ещё не начинавшие работу, в списке слева неактивны. Контекстные окна прерываний (подтверждение плана, ручная приёмка с комментарием и чеклистом критериев, доработка входа с вариантами формулировки от контролёра) и модальное окно lessons learned (вкладки авто/ручных исправлений с чекбоксами и применением через выбранный runtime). Клик по карточке шага переключает панель на этот шаг; вкладка "Ошибки" показывает первой ошибку прогона, далее неудачные попытки и артефакты `__err-*`; вкладка "Лог" - события шага; инструменты - вызовы `read_file`/`list_dir`/`run_command` и MCP у provider-шагов (статус, аргументы, длительность, размер); статистика - токены, стоимость, runtime с моделью, tier и effort, счётчики служебных маркеров циклов (состав группы по клику); текстовые артефакты кликабельны - содержимое открывается в отдельном окне. Тексты выдаются только при privacy `full`, иначе - размер и контрольная сумма. Прогон в статусе `completed` не предлагает повтор; прогон с ошибкой даёт **"Повторить с начала"** (перезапись артефактов всех шагов, сброс чекпоинта; находки ошибок, возвраты и lessons learned сохраняются) и **"Повторить с последнего удачного шага"** (перезапись только неуспешных шагов).
- **Агент, вкладка Роли** (`/agent?tab=roles`) - роли-файлы `.agents/roles/<папка>/<id>.md`: селектор папки, карточки ролей, кнопка **"Добавить роль"** открывает визард (папка - существующая или новая, id, название; скелет секций создаётся автоматически). Модальный редактор: форма frontmatter (title, domain, skills, mcp, tools, defaultTier/defaultEffort) + markdown-тело с секциями (Роль, Правила работы, Принципы работы, Оценка входных данных, Оценка своей работы) + вкладка исходника файла; **"Удалить роль"** удаляет файл.

- **Агент** `/agent` - вкладка **"Агент"**: стриминговый диалог с агентом. Над полем ввода - рабочая директория и ветка: папка без git показывает кнопку "✕ Git" (клик - предложение `git init`); в репозитории селектор веток с переключением и пунктом "Создать новую ветку…" (модалка с вводом имени, `git checkout -b`). Внизу справа перед **Отправить** - исполнитель (один селектор с группами "Провайдеры AI SDK" и "Рантаймы"), модель по одному из четырёх tiers (подписана конкретная модель выбранного источника) и effort (low/medium/high/max). Поле ввода поддерживает автодополнение: `/` открывает меню (навыки - `/<имя>`: у рантайма нативный вызов, у провайдера раскрытие на сервере; master skills - `/master:<id>`; запуск workflow - `/workflow:<id>` и агенты-роли - `/agent:<id>`, только в Direct; в режиме workflow - подсказка навыков ролей workflow), `@` - поиск файлов и папок рабочей папки (клик по папке открывает её, вставляется путь файла); навигация стрелками, выбор Enter/Tab, закрытие Esc. Команды раскрываются на сервере: навык и роль - в промт (рантайм) или системный промт (провайдер), `@путь` провайдеру разворачивается в содержимое файла. Master-навыки и workflow доступны и в отдельно запущенном рантайме - нативные команды `/master:<id>` и `/workflow:<id>` создаёт синк консоли (Настройки → Навыки → "Команды рантаймов"). Провайдер выполняет промт через LangGraph-граф с LangChain-моделью (`POST /api/agent/chat`: стрим ответа, json-render UI-спеки в ответе, effort → `reasoning_effort`; инструменты - `read_file`, `list_dir`, `run_command` в рабочей директории, `run_command` проходит guard-политику репозитория, плюс инструменты включённых MCP-серверов реестра - вызовы показываются строками "инструмент <имя>: статус"); рантайм - headless-CLI в выбранной рабочей директории с передачей model/effort там, где флаг поддержан (claude `--model/--effort`, codex `-m/-c model_reasoning_effort`, opencode `-m/--variant`, kimi `-m`; zcode - параметры фиксируются в задаче), вывод стримится из лог-файла. Оба пути видны в "Мониторинг → Задачи". Реплики диалога несут время отправки и время ответа; между днями общения стоят разделители дат. Открытый диалог занимает верх панели (появление и закрытие - анимацией высоты), под ним поле ввода, ниже история: в Direct - direct-чаты плюс сессии рантаймов папки, в workflow - запуски со статусами; при открытом диалоге история анимированно сжимается в заголовок, клик по заголовку или блоку открывает модальное окно с виртуализированным списком, строки кликабельны: direct-чат возвращается в диалог, сессия рантайма - превью транскрипта (ввод заблокирован до "Новый диалог"), запуск - страница run. Каждый завершённый ответ Direct-чата сохраняется локально в `.agents/console/direct/<id>/` (chat.json с сообщениями и временем реплик, папки input/ и output/ - резерв под будущую передачу файлов; каталог исключён из git). Открытые вкладки раздела остаются смонтированными при переключении - история диалога и несохранённые правки редакторов не теряются. Провайдер по умолчанию - звезда ★ на карточке провайдера или панель "AI SDK" в "Настройки - Основные" (без выбора - Ollama). Выбор исполнителя сохраняется на сервере и восстанавливается после перезагрузки.
- **Рантаймы** `/runtimes` - карточки runtime и внутренняя вкладка провайдеров. Пространство конкретного runtime остаётся на `/runtime/<id>`.
- **Дизайн** `/design` - рабочее место дизайн-контекста обязательной директории (меняется в "Настройках → Рабочих папках"), внутренние вклады: **Обзор** - панель **Design pack** (DESIGN.md, BRAND.md, design/ui-kit.md, design/components.json; кнопки "Создать из пресета", "Синхронизировать в рантаймы"/"Убрать блоки" - managed-блок `harness-design` в CLAUDE.md/AGENTS.md папки), панель **"Провайдеры дизайна"** (готовность Claude Design - команда `/design`, Open Design - MCP + CLI od, Figma MCP - OAuth; кнопка "Задача" с префиллом), панель **"Задача"** (единый запуск: рантайм - новая headless-сессия, провайдер - агентный цикл с MCP open-design/figma, отдельная сессия - headless-resume; 4 кнопки-контура: обновить кит из DESIGN.md, компонент из макета Figma, аудит интерфейса по токенам, бренд-паспорт из open-design) и **"Артефакты open-design"** (list-инструменты MCP, только чтение); **Токены** - редактор DESIGN.md (пресеты, свотчи 18 ролей, слайдеры-мультипликаторы, предпросмотр файла/гайда, сохранение с lint); **Гайд** - секционный редактор markdown-тела DESIGN.md (карточки по H2, подсветка синтаксиса, исходник/предпросмотр); **Бренд** - секционный редактор BRAND.md (шаблон, заполнение задачей, секции/исходник/предпросмотр); **UIKit** - редактор design/ui-kit.md с подсветкой; **Компоненты** - менеджер design/components.json (списки web/mobile, добавление/удаление, пересканирование, регистрация кита); **Навыки** - группа design (тогглы, "В Задачу"); **Инструменты** - design-пресеты каталога MCP: figma, open-design, playwright, webmcp, excalidraw, google-design, stitch - установка и включение в один клик. Детали - [docs/design.md](../../docs/design.md).
- **`/runtime/<id>`** - вкладки: Обзор (расширенная статистика + MCP), Диагностика (проблемы с hint'ами и кнопкой "Исправить"), Навыки и скрипты (под-вкладки Runtime Skills / Harness Skills / Scripts / MCP), Сессии (список по рабочей папке → превью транскрипта → ответ), Процессы (таблица с cpu/mem/uptime, стоп SIGTERM→SIGKILL, рестарт для .app), Память (memory-файлы этого рантайма: рабочие папки + "Глобальные"). Звезда ★ в шапке - выбрать рантайм по умолчанию.
- **Навыки, MCP, Плагины, Рабочие папки** - вкладки раздела "Настройки" (`/settings?tab=skills|mcp|plugins|workspaces`); состав - в строке "Настройки" ниже.
- **Знание** `/memory` - документы рабочих папок (Docs; вложенные рабочие папки в дереве родителя скрыты), вики OpenWiki, графы Graphify и вкладка **"Память"** (memory-файлы рантаймов); всё читается с диска. У собранной вики - кнопка **"Граф"**: встроенный визуализатор openwiki; сборка - "Собрать/Обновить" (openwiki CLI с LLM-провайдером) или **"через агент ★"** (headless-сессия рантайма с интеграцией openwiki - страницы пишет сам агент своей моделью); у Graphify граф каждой папки собирается отдельным воркспейсом в хранилище `graphify/<имя>/graphify-out/` (несколько независимых графов; запросы к графу папки - `graphify query "…" --graph graphify/<имя>/graphify-out/graph.json`), кнопки: **"Собрать"/"Обновить"** (инкрементальный `graphify extract --out` + `cluster-only` - graph.html и GRAPH_REPORT.md), **"через runtime ★"** (полная сборка код + доки с именами сообществ), **"Wiki"** (статьи markdown из графа - `graphify export wiki`, `graphify-out/wiki/`), **"Статьи wiki"** (просмотр: дерево статей слева, markdown справа), **"Опубликовать"** (просмотр graph.html в iframe; требует интернета для CDN-библиотек) и **"Граф знаний"** (открыть опубликованный граф папки). Блок **"Воркспейсы"**: объединение собранных вики нескольких папок для агентского поиска (openwiki_search идёт по всем участникам воркспейса), активный воркспейс по папке. Детали - в [docs/operations.md](../../docs/operations.md) ("Память").
- **Мониторинг** `/monitoring` - вкладка **"Задачи"**: запуски консоли (промты в headless-сессиях, запросы провайдерам, сборки OpenWiki/Graphify) с бейджами исполнителя (рантайм/провайдер/инструмент) и модели, ссылкой на сессию, фильтром "Активные / Все / Завершённые" (по умолчанию - активные). Задачи выполняются параллельно. Вкладка **"Статистика"** - под-вкладки **"Сводка"** (runs, attempts и токены, роли, модели и стоимость workflow, подписка и блок AgentPlane - версия, инициализация, число задач по статусам) и **"Heatmap"** (использование harness по дням за 3/6/12 месяцев; клик по дню - таблица по инструментам: запуски, завершено, ошибки, типы задач). Детали - [docs/operations.md](../../docs/operations.md) ("Мониторинг: задачи") и [docs/stats.md](../../docs/stats.md).
- **Настройки** `/settings` - вкладка **"Основные"**: панель **"AI SDK"** (провайдер AI SDK по умолчанию для "Агента" - активный провайдер или Ollama; поле "Сообщений в истории диалога" - сколько последних реплик direct-чата уходит модели, 0 - все, пусто - 20; кнопка "Установить провайдера" - модал с выбором пресета и карточкой заполнения) и все кейсы провайдеров - исполнители задач ("Исполнение команд", "Создание навыка", "Оптимизация": рантайм или активный провайдер; для "Оптимизации" значение "По умолчанию" - провайдер по умолчанию, Ollama) и инструменты памяти ("OpenWiki (сборка вики)", "Graphify (сборка графа)": провайдер реестра или "Вручную"). ## MCP: глобальный реестр и синк

Правило: таргет управляет своими именами - текущим реестром ∻ тем, что сам писал в прошлый синк (иначе сервер, покинувший реестр - например, при выключении плагина, - остался бы в файлах навсегда). Чужие записи в файлах не изменяются. Отключение (toggle) удаляет сервер из файлов, но сохраняет запись в реестре (вернуть - toggle обратно).

| Таргет | Формат |
|---|---|
| `<repo>/.mcp.json` | `mcpServers` (общий проектный, все рантаймы) - по глобальному toggle |
| Claude Code (user) | `claude mcp add-json/remove -s user` (CLI; fallback - мерж `~/.claude.json`) |
| Codex global | `~/.codex/config.toml`, секции `[mcp_servers.<name>]` (+`.env`) - посекционный редактор |
| Cursor global | `~/.cursor/mcp.json` (`mcpServers`) |
| OpenCode global | `~/.config/opencode/opencode.jsonc`, ключ `mcp` (`type: local/remote`) |
| ZCode / Kimi global | глобального MCP-ключа нет - работает только проектный `.mcp.json` |

Override рантайма (чипы в реестре, тогглы в space) действует на пользовательский конфиг этого рантайма: `final = override ?? глобальный enabled`. Транспорт сервера (command/args/env или url/headers) редактируется через шестерёнку на карточке - `PATCH /api/mcp { transport }`; включённость и override-чипы при этом сохраняются.

## Сессии и ответы

Источники: Claude - `~/.claude/projects/<слаг-папки>/*.jsonl`; Codex - `~/.codex/sessions/**` (cwd в `session_meta`); Kimi - `session_index.jsonl` (workDir); ZCode - `~/.zcode/cli/rollout/model-io-sess_*` (без привязки к папке, связь с репо - через plan-файлы); OpenCode - `opencode.db` (SQLite через `sqlite3 -readonly`, колонка `directory` сессии). Cursor - история в SQLite, не поддерживается. Ожидание ввода: последний ход завершён (assistant / task_complete / completedAt), файл не изменяется ≥ 2 мин, процессы работают.

Ответ в сессию - headless-resume CLI: `claude -p --resume <id> "…"`, `codex exec resume <id> "…"`, `node …/zcode.cjs -p --resume sess_<id> "…"`, `kimi --session <id> -p "…"`, `opencode run -s <id> "…"` (таймаут 120 с, вывод возвращается в UI; сессия продолжается отдельным процессом).

## Рантайм по умолчанию и запуск промтов

★ на странице рантайма выбирает рантайм по умолчанию (хранится в состоянии). Кнопка "Исправить" в диагностике формирует промпт по проблеме (заголовок, детали, рекомендация + требование соблюдать AGENTS.md/guard) и запускает его в **новой headless-сессии** рантайма по умолчанию (`claude -p`, `codex exec`, `zcode -p`, `kimi -p`, `opencode run`): процесс отвязанный, вывод - в `.agents/console/runs/<ts>-<runtime>.log`, сессия автоматически появляется в общем списке сессий. Тот же механизм доступен как `POST /api/prompts/run` ({prompt} или {issue}). Безопасность: allowlist бинарников, санитайзинг аргументов, без оболочки.

## Производительность

- микрокеш дашборда (TTL 5 с + дедупликация параллельных пересчётов, инвалидация при мутациях) - повторные открытия и опрос каждые 10 с мгновенны;
- страница `/runtime/<id>` пробит только выбранный рантайм (не все шесть);
- один снапшот `ps` на цикл проба (TTL 2 с) вместо спавна на каждый рантайм; перед сигналами процессам - всегда свежий срез;
- `scanLimit` у обходов ФС - гигантские каталоги (~/.cursor/extensions) не съедают секунды.

## Навыки

Установка из skills.sh: поиск - `bunx skills find <query>` (HTTP API как фолбэк), в результатах ссылка на страницу навыка; в карточке - описание (цепочка: снапшот реестра → страница навыка → GitHub → DeepWiki; iframe как последний фолбэк) и аудит безопасности. Установка - `bunx skills add <pkg> -y` (SSE-терминал с вводом). Удаление - `bunx skills remove <name> -y` с ручной зачисткой-фолбэком (.agents/skills/<name>, skills-lock.json, симлинки агентов). Создание - форма → промпт → headless-сессия рантайма задачи.

Глобальный уровень навыков - один toggle "Использовать глобальные навыки" (страница "Навыки и MCP"): включён - все глобальные навыки в каждом рантайме включены, выключен - выключены. Override конкретного навыка или MCP-сервера - тогглом в пространстве рантайма (под-вкладки Runtime Skills / Harness Skills (.agents/skills) / Scripts / MCP). Дискавери read-only: `~/.claude/skills`, кэш плагинов ZCode, `~/.cursor/skills-cursor`, `~/.codex/skills|prompts`, агенты OpenCode + проектные плагины, `extra_skill_dirs` Kimi. Файлы рантаймов не изменяются и не удаляются.

## Состояние консоли

`.agents/console/state.json` - локальный файл вне Git (атомарная запись): реестр MCP, оверлеи навыков, рабочие папки (пути можно задавать через `~`), результаты последнего синка. Переопределяется переменной `HARNESS_CONSOLE_STATE` (тесты).

## Как читается активность

| Статус | Условие |
|---|---|
| `активен сейчас` | свежий сигнал ≤ 5 минут |
| `был активен` | сигнал в пределах выбранного окна (1 ч / 24 ч / 7 дней / всё) |
| `неактивен` | сигналы старше окна |
| `не установлен` | нет маркеров установки рантайма (disabled) |
| `нет данных` | рантайм обнаружен в конфигах, но адаптер сигналов не подключен |

Источники сигналов - только mtime файлов и первые строки rollout-логов; содержимое сессий читается лишь при открытии превью и не покидает машину.

│   │                # mcp/sync (реестр+таргеты), processes (ps+действия),
│   │                # issues, skills (оверлеи), sessions/ (claude|codex|kimi|zcode)

### Подключить новый runtime

1. Конфиг в harness: `.agents/runtime/<id>/config.json` (создаст карточку).
2. Адаптер `src/runtimes/<id>.ts`: `probeSignals`/`isInstalled`/`processPattern` (активность), `detectIssues` (диагностика), `listSkills`, `listSessions`/ `getSession`/`awaitingInput`/`replyCommand`/`runCommand` (по желанию).
3. Одна строка в `ADAPTERS` в `src/runtimes/index.ts`.
4. UI-плагин (опционально): `src/plugins/runtimes/<id>.ts` - монограмма/цвет карточки + строка в `src/plugins/runtimes/index.ts`. Без плагина рантайм получает оформление по умолчанию; список рантаймов в store приходит с сервера (`GET /api/runtimes/list`), так что UI подхватывает новое подключение сам.

`ProbeContext` даёт адаптерам `repoRoot`, `home`, `workspaces` и файловые хелперы - адаптеры не ходят в файловую систему напрямую и легко тестируются.

### Порядок мутаций и кеш

Все тогглы применяются по схеме "сначала файл, потом store": API пишет `.agents/console/state.json` (атомарно) и только после успеха отвечает клиенту; клиентский zustand-store обновляется после подтверждения сервера. Данные вкладок пространства рантайма (процессы/навыки/сессии) кешируются в store (`fetchTabData` с TTL) - переключение вкладок мгновенное, протухшие данные обновляются в фоне; серверные страницы стримятся со скелетоном (`loading.tsx`).

## Совместимость с harness

- Консоль **читает** `.agents/runtime/**`, `.mimosa/`, каталоги данных рантаймов; **пишет** только в `.agents/console/state.json`, MCP-конфиги (исключительно имена из реестра) и не изменяет файлы навыков.
- Секретные паттерны (`.env*`, `*.pem`, `id_rsa`, `secrets/`) не затрагиваются.
- Действия над процессами выполняются только после перепроверки PID по паттерну рантайма; UI запрашивает подтверждение.

Модульность - два уровня:

1. **Источник правды о списке рантаймов** - `.agents/runtime/<vendor>/config.json`. Карточка (модели, capabilities, hooksSupport, vendorAdapter, права) строится из конфига; новый вендор в harness появляется на дашборде автоматически.
2. **Адаптеры актуальных сигналов** - `src/runtimes/<id>.ts`. Без адаптера карточка работает, но со статусом "нет данных"; ошибка адаптера не приводит к сбою дашборда.

### Подключить новый runtime

1. Конфиг в harness: `.agents/runtime/<id>/config.json` (создаст карточку).
2. Адаптер: `src/runtimes/<id>.ts` -

   ```ts
   import { join } from "node:path";
   import type { RuntimeAdapter } from "@/core/types";

   export const myAdapter: RuntimeAdapter = {
     id: "<id>",                       // = имя каталога конфига
     displayName: "My Runtime",
     processPattern: /my-runtime/,     // опционально: детектор процессов
     async probeSignals(ctx) {         // опционально: актуальные сигналы
       const mtime = await ctx.fs.mtimeOf(join(ctx.home, ".my-runtime", "state.db"));
       return mtime ? [{ at: mtime, scope: "machine", source: "~/.my-runtime/state.db" }] : [];
     },
   };
   ```

3. Одна строка в списке `ADAPTERS` в `src/runtimes/index.ts`.

`ProbeContext` даёт адаптерам `repoRoot`, `home` и файловые хелперы (`newestMtime`, `collectFiles`, `headJsonLine`), так что адаптеры не ходят в файловую систему напрямую и легко тестируются.

## Совместимость с harness

- Консоль **только читает** `.agents/runtime/**`, `.mimosa/`, `.zcode/plans/` и mtime-маркеры в домашнем каталоге; ничего не пишет в harness-конфиги.
- Секретные паттерны (`.env*`, `*.pem`, `id_rsa`, `secrets/`) не затрагиваются.
- Классификация и сборка DTO покрыты `bun test` (чистые функции + фикстуры).
