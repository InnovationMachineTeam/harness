# Детекция дрейфа документации и кода

Дрейф - расхождение между документом и кодом: документ описывает то, чего в коде нет, или код содержит существенную логику, не отражённую в документе. Правило репозитория: расхождение документации с кодом - дефект; этот навык его находит.

Адаптация skill egm_drift_report из google/elephant-goldfish-model (Apache-2.0).

## Входные данные

- каталог документов: по умолчанию `docs/`; другой каталог запроси у пользователя;
- целевые исходники: репозиторий рабочей папки.

Обрабатывай документы последовательно, по одному за раз: это удерживает буфер инструментов и исключает смешение документов.

## Порядок работы для каждого документа

1. Контекстуализация. Прочитай документ целиком. Определи намерение документа, описанные изменения и упомянутые файлы, классы, функции, схемы и команды.
2. Поиск исходников. Для каждого упомянутого объекта найди соответствующий код поиском по репозиторию (grep, serena или codegraph - что доступно). Если путь объекта неявный и поиск по имени не дал результата, не додумывай: зафиксируй в отчёте, что документу нужна явная ссылка на исходник, и запроси у пользователя.
3. Верификация. Прочитай текущее состояние найденного кода. Не опирайся на память и прежние чтения: состояние кода проверяется в этом прогоне.
4. Детекция дрейфа. Сравни описание документа с фактическим кодом по категориям:
   - Missing Features: логика, описанная в документе, отсутствует в коде;
   - Incomplete Models: классы, структуры или схемы существуют, но без полей или поведения из документа;
   - Logic Shortcuts: вместо описанной динамики в коде хардкод, заглушка или упрощение;
   - Architectural Divergence: код использует другие паттерны, библиотеки или структуру, чем описано.
5. Обратный дрейф. Для области кода, которой посвящён документ, проверь наличие существенной логики, не отражённой ни в этом документе, ни в связанном README. Существенная логика меняет поведение или контракт; деталь реализации вне назначения документа - не дрейф.
6. Фильтрация. В отчёт попадают только расхождения. Полное совпадение документа и кода записывается строкой "No drift detected".

## Отчёт

Один сводный файл: `.agents/.tmp/<ГГГГ-ММ-ДД>_DRIFT_REPORT.md`. Для каждого документа - раздел по шаблону:

```markdown
## <ИМЯ_ДОКУМЕНТА>

- <категория>: <расхождение> (документ: <место>; код: <файл>:<строки>)
```

При полном совпадении: единственная строка "No drift detected". Файл дополняй по мере обработки документов; непроверенные объекты перечисли с причиной.

## Правила

- Упомянутый в документе объект без реализации в коде - дрейф; отсутствие реализации не бывает "предполагаемым".
- Каждое расхождение в отчёте имеет две стороны: место в документе и файл со строками в коде.
- Не исправляй документ и код: навык детектирует, исправление - отдельная задача по отчёту.
- Каталоги `node_modules/`, `.git/`, кеши и сгенерированные каталоги из поиска исключай.

## Условие завершения

Все документы каталога обработаны последовательно; отчёт содержит раздел по каждому документу; каждое расхождение имеет категорию, место в документе и ссылку на код; непроверенные объекты перечислены с причиной.
