# Старт рабочей сессии

Начинай работу с восстановления состояния: что сделано, что не завершено, какая задача текущая. Не пиши код, пока цель задачи не определена.

## Порядок работы

1. Прочитай контекст предыдущей работы: заметки передачи (навык agent-handoff), TODO-комментарии в затрагиваемых файлах, задачи в работе.
2. Проверь состояние репозитория: `git status` (незакоммиченные изменения), `git log --oneline -5` (последние изменения), наличие упавших проверок.
3. Определи текущую задачу. Если задача не ясна из контекста, задай пользователю один уточняющий вопрос; не выбирай цель самостоятельно.
4. Составь план до правок: шаги, затрагиваемые файлы, проверки. Для сложной задачи разбей работу на шаги и назови объём первого шага.
5. Сверь план с ограничениями активного профиля (лимиты AGENTS.md): превышение лимита - сигнал упростить план, а не расширять работу.

## Правила

- Не начинай правки до определения цели и границ задачи.
- Незакоммиченные изменения, происхождение которых не ясно, не перезаписывай; сначала выясни их владельца.
- Планируй в числах: количество шагов, файлов, ожидаемое время проверок.
