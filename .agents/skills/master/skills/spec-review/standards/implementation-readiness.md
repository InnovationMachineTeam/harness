# Стандарт готовности к реализации

Стандарт для планов реализации: инженер без доступа к автору выполняет документ без возвратов на уточнение.

Пункты проверки:

1. Каждая точка реализации, требующая решение, имеет его в документе: формат данных, обработка ошибок, поведение при повторном вызове, границы значений.
2. Входы, выходы и побочные эффекты каждого нового компонента названы явно.
3. Зависимости перечислены с владельцами и порядком действий: библиотеки, сервисы, миграции, смежные команды.
4. Миграция, обратная совместимость, откат и частичное включение рассмотрены, если изменение затрагивает существующее поведение.
5. Каждое требование имеет проверяемый критерий приёмки: тест, наблюдение или измерение.
6. Заявленные границы исполнимы: инженер может проверить соблюдение границы.
7. Трудоёмкость соотнесена с текущим кодом: затронутые места перечислены, сопутствующие правки не скрыты.

Вердикт стандарта: готов, готов после доработки (список решений с владельцами), не готов.
