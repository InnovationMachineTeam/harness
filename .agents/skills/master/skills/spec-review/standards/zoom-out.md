# Стандарт простоты и переиспользования (zoom-out)

Стандарт для проверки документа с высоты системы: решение решает корневую проблему минимальными средствами.

Пункты проверки:

1. Корневая проблема названа отдельно от решения; подмена проблемы решением - находка Blocker.
2. Каждый новый компонент, утилита или слой обоснован текущей потребностью; элемент "на будущее" без потребителя - находка.
3. Существующие компоненты и библиотеки рассмотрены до предложения новых; утверждение "готового нет" подтверждено поиском по коду; порядок рассмотрения - лестница переиспользования: существующий код, стандартная библиотека, возможность платформы, установленная зависимость, минимальный новый код последним.
4. Преждевременная детализация отсутствует: псевдокод и внутренности реализации не подменяют контракт.
5. Архитектурные тупики отсутствуют: решение не блокирует очевидные следующие шаги (масштабирование, миграция, смена хранилища).
6. Связность оценена: типовое изменение требований затрагивает приемлемое число компонентов.
7. Каждая альтернатива "меньше механизма" (удаление слоя, использование готового) либо принята, либо отклонена с причиной.
8. Осознанное упрощение с известным пределом оформлено как решение: назван предел и условие пересмотра; замалчиваемое упрощение - находка.

Каждый пункт либо выполнен, либо это находка с измерением: необходимость, переиспользование, тупик, связность.
