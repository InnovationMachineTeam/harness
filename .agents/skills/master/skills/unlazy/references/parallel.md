# Параллельные конвейеры и листья

Скоупы и leases владения координируют параллельные процессы unlazy. Они предотвращают случайную перекрёстную сертификацию и отклоняют пересечение заявленного владения. Они не изолируют shell-команды, не навязывают права операционной системы и не остановят процесс, игнорирующий протокол.

## Раскладка

```text
.agents/.tmp/unlazy/
  <scope>/
    PLAN.md
    GATES.md
    gates/
      leaf-*.md
      node-*.md
    status.log
    session
    hook-state.json
  locks/
```

Держи `.agents/.tmp/unlazy/` вне git. Legacy-раскладка одного конвейера - `GATES.md` плюс `gates/*.md` в корне проекта - остаётся доступной для solo-работы.

## Резолв скоупа

Скоупный вызов чекера выбирает один конвейер в порядке:

1. `--scope <id>`
2. `UNLAZY_SCOPE`
3. единственный присутствующий скоуп
4. legacy-раскладка, когда скоупного конвейера нет

Stop-хук дополнительно может использовать привязку `session_id` текущей сессии Claude Code, записанную `--bind`. Привязка ассоциирует сессию со скоупом; она не является аутентификацией.

Когда скоупов несколько и ни один не резолвится, чекер отказывается работать вместо прогона всех реестров. Stop-хук позволяет остановку с диагностикой вместо блокировки сессии на неизвестном конвейере.

Идентификаторы скоупов соответствуют `[A-Za-z0-9][A-Za-z0-9._-]{0,63}` и не равны `.` или `..`. Разделители, обход каталогов и абсолютные пути не используются.

## Что изолирует скоуп

Скоуп ограничивает собственные механизмы unlazy:

- поиск гейтов по умолчанию
- цель журнала статуса
- резолв и прогресс-состояние Stop-хука
- метку владельца lease

Скоуп не ограничивает процесс `CHECK:`. Проверки наследуют доступ операционной системы и могут читать и писать вне скоупа. Когда сами команды должны быть изолированы, используй отдельные worktree или более сильную изоляцию процессов.

## Заявки владения

Пути объявляются до первого гейта:

```markdown
OWNS: src/api/**, tests/api/**
```

Абсолютные пути и любой путь с сегментом `..` отклоняются. Каждый параллельно запускаемый лист объявляет все пути, которые может менять, и claim'ит их до работы:

```text
node <skill-dir>/scripts/gate-check.mjs --scope api --leaf leaf-1.2.1 --claim
```

Claim проверяет все существующие leases и пишет новый под одним глобальным lease-локом. Два одновременных конфликтных claim не могут оба пройти. Claim - операция всё-или-ничего.

Пара скоуп/лист эксклюзивна, пока существует lease. Повтор того же claim отклоняется, даже если новые пути не пересекаются, и отклонённая попытка не переписывает исходный набор путей lease. Освободи именно этот лист перед повторным claim. Это защищает от двух воркеров с одной логической идентичностью, каждый из которых считает lease своим.

Каталоги локов содержат JSON-метаданные владельца. Unlazy намеренно не ломает внешне устаревший лок: удаление путей живого владельца может пропустить двух наследников одновременно. Если процесс умер с локом, сначала убедись, что записанный процесс не запущен и никакая операция unlazy не может ещё держать лок, затем удали вручную только этот конкретный брошенный лок. Весь каталог локов при активной работе не чистится. Локи записей одобрений восстанавливаются по тому же правилу.

Детекция пересечений намеренно консервативна. Она может отклонить два globs, непересечение которых доказала бы полная машина пересечений, особенно globs с wildcard в середине сегмента. Неуверенная пара никогда не помечается безопасной. Избыточный конфликт - повод упростить пути до непересекающихся или исполнять последовательно.

Примеры:

| Первая заявка | Вторая заявка | Результат |
|---|---|---|
| `src/api/**` | `src/web/**` | не пересекаются |
| `src/shared/**` | `src/shared/util.mjs` | конфликт |
| `src/a*.mjs` | `src/ab*.mjs` | конфликт: пересечение возможно |
| `**` | `docs/**` | конфликт |

Leases покрывают только заявленные пути и только участников, соблюдающих протокол. Это записи координации, не изоляция записи.

После реверификации родителя и ручного ревью освободи именно этот лист и запиши освобождение до повышения любого зависимого:

```text
node <skill-dir>/scripts/gate-check.mjs --scope api --release --leaf leaf-1.2.1
node <skill-dir>/scripts/gate-check.mjs --scope api --log "leaf-1.2.1 lease released"
```

Весь скоуп освобождается только после того, как все листья завершены, все волны диспетчеризации терминальны, а веточная, корневая и финальная агрегатная верификация выполнены. Скоуп-форма до этого момента - только явное восстановление после проверки, что записанный владелец исчез:

```text
node <skill-dir>/scripts/gate-check.mjs --scope api --release
```

Неизвестный `--leaf` - ошибка. Чекер никогда не молча подставляет первый реестр.

## Параллельные обновления реестра

Чекер сериализует каждое обновление файла гейтов и коммитит атомарно. Перед применением завершённой проверки он перечитывает реестр и подтверждает, что идентификатор гейта и поля оракула совпадают с тем, что исполнялось. Если команда, ожидание, рабочий каталог или другая привязанная часть оракула изменились в полёте, устаревший результат отбрасывается.

Сохрани исходный стиль LF или CRLF реестра. Вставка отсутствующей строки доказательства не меняет постороннее содержимое. Вывод результатов детерминирован в порядке гейтов даже при `--jobs <N>`.

Журнал статуса - append-only:

```text
node <skill-dir>/scripts/gate-check.mjs --scope api --log "leaf-1.2.1 verified"
```

Append-only снижает потери обновлений; он не заменяет живые поля состояния в PLAN.md.

## Хук-состояние по ключу сессии

Stop-хук ключует прогресс-состояние по разрешённому скоупу и текущей сессии. Параллельные вызовы хука сериализуют обновление. Завершение или исчезновение реестра очищает устаревшее состояние. Одна сессия не может израсходовать шесть блоков без прогресса другой сессии.

Хук закрепляется установщиком `--scope` или резолвит привязку сессии, записанную:

```text
node <skill-dir>/scripts/gate-check.mjs --scope api --bind <session-id>
```

Сохранённый идентификатор сессии - не секрет и не доказательство идентичности.

## Выбор уровня изоляции

- Одно рабочее дерево и несколько скоупов - для работы с преобладающим чтением или листьев с простым непересекающимся владением.
- Один worktree на конвейер - когда локальный вывод воркспейса или генерируемые файлы сталкиваются. Отдельные каталоги кеша настраиваются, если записи в кеш могут конфликтовать; worktree не изолируют внешние кеши и сервисы.
- Изоляция уровня ОС или контейнера - для недоверенных команд. Одобрения и leases unlazy - не песочница.

Параллелизм меняет время по стене, а не стандарт доказательства. Реверификация родителя и интеграция веток остаются обязательными.
