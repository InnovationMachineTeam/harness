# Диспетчеризация нативных агентов

Контракт применяется, когда orchestrated-режим имеет два и более независимых листа READY. Unlazy записывает нативные запуски; сессии агентов создаёт хост.

Для одной волны каждый нативный вызов запуска и каждая запись `start` завершаются до первого ожидания, join, чтения результата или записи возврата.

## Открыть и запечатать волну

Сначала claim каждого листа. Лишние листья READY сверх текущего лимита параллелизма хоста уходят в более поздние волны. Затем открой одну волну с точными идентификаторами:

```text
node <skill-dir>/scripts/dispatch-check.mjs open --scope <scope> --wave ready-1 --leaf leaf-1.1.1 --leaf leaf-1.1.2
```

Для каждого листа вызови нативный неблокирующий инструмент запуска хоста и запиши возвращённый непрозрачный не-секретный хэндл:

```text
node <skill-dir>/scripts/dispatch-check.mjs start --scope <scope> --wave ready-1 --leaf leaf-1.1.1 --handle <host-agent-id-1>
node <skill-dir>/scripts/dispatch-check.mjs start --scope <scope> --wave ready-1 --leaf leaf-1.1.2 --handle <host-agent-id-2>
```

Запечатай волну до ожидания любого результата:

```text
node <skill-dir>/scripts/dispatch-check.mjs seal --scope <scope> --wave ready-1
```

Seal проваливается, пока у каждого заявленного листа нет отличного хэндла старта. `return` до seal отклоняется. Эти отказы ловят серийный паттерн: запустить один лист, дождаться, и только потом запустить следующий.

Когда нативный агент завершился, запиши возврат до реверификации родителя:

```text
node <skill-dir>/scripts/dispatch-check.mjs return --scope <scope> --wave ready-1 --leaf leaf-1.1.1
```

Возврат фиксирует завершение планировщика, включая провальный результат воркера. Он не помечает лист VERIFIED: родитель по-прежнему исполняет гейты листа и проверяет ручные доказательства.

Проверь завершённую волну:

```text
node <skill-dir>/scripts/dispatch-check.mjs status --scope <scope> --wave ready-1
```

`status` завершается с 0, только когда каждый заявленный лист вернулся. Состояние и метки времени живут в `.agents/.tmp/unlazy/<scope>/dispatch.json`; события жизненного цикла также дописываются в журнал скоупа. Атомарный переход состояния авторитетен: если последующая запись в журнал аудита отклонена, команда перехода всё равно успешна и печатает ограниченное предупреждение. Инспектируй состояние, прежде чем решать следующее действие; не повторяй переход вслепую.

Загрузчик состояния требует строковых идентификаторов, хэндлов и причин отказов плюс возможной истории переходов: возврат требует запечатанной волны со всеми стартами, терминальные метки времени существуют и следуют за предыдущими переходами, полностью вернувшаяся волна полна. Ручная правка невозможного терминального состояния проваливается закрыто. Сводка `gate-check.mjs --scope <scope>` включает агрегатное состояние и не печатает ALL MET, пока волна открыта, запечатана, брошена или некорректна.

## Адаптер Harness

- **Claude Code:** фоновые субагенты запускаются параллельно. Запусти каждый лист фоновым вызовом Agent (`run_in_background: true`), запиши каждый возвращённый идентификатор задачи и seal до чтения любого результата. Передние (foreground) вызовы Agent один за другим не применяются.
- **ZCode:** та же схема с фоновым запуском субагентов (`run_in_background`); хэндл - идентификатор агента из результата запуска.
- **Консоль Harness:** для регулярного fan-out используй workflow-движок: узлы с `dependsOn` и `outputControl` дают семантический барьер и реверификацию силами движка. CLI-волна dispatch-check открывается, когда поверхность хоста даёт отдельный нативный хэндл для каждого агента; иначе сохрани скрипт workflow и прогресс как доказательство ветки, не заявляя CLI-верифицированную волну.
- **Shell-процессы не заменяют нативных агентов:** ферма процессов теряет нативное планирование и наблюдаемость текущей сессии.

## Отказ и откат

Если нативный запуск провалился до возврата хэндла, оставь волну открытой, почини проблему запуска и повтори этот лист. Частичная волна не запечатывается. Если восстановление невозможно, сохрани аудит вместо изобретения хэндла или удаления состояния:

```text
node <skill-dir>/scripts/dispatch-check.mjs abandon --scope <scope> --wave ready-1 --reason "<ограниченная непустая причина>"
```

Брошенная волна терминальна, `status` завершается с 1. Stop-хук не блокирует на ней, но выдаёт ограниченное сообщение HANDOFF REQUIRED с именем волны, без копирования свободной причины в привилегированное сообщение хоста. Причину для передачи извлекай из dispatch.json. Если у хоста нет неблокирующего запуска, запиши ограничение в PLAN.md, исполни заявленный последовательный откат и не открывай и не описывай параллельную волну.

Открытие волны - заявка на исполнение. Хэндлы не изобретаются, передний результат не записывается как start, одновременная работа не доказывается скоростью исполнения команд.

## Граница доказательства

Барьер запуска доказывает, что хост принял каждый нативный старт до того, как драйвер принял возврат. Он не доказывает честность воркера, точное пересечение по CPU, изоляцию файловой системы или успешную интеграцию. Leases, реверификация родителя и веточные гейты остаются отдельными требованиями.
