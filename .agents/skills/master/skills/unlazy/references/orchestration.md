# Orchestrated режим

Оркестрация применяется, когда один контекст не удерживает задачу и её верификацию с полным вниманием. Драйвер отвечает за планирование, диспетчеризацию, независимую верификацию, интеграцию и корневой отчёт.

## Состояния и пути

Состояния листа - ровно одно из:

- WAITING: хотя бы один идентификатор в Needs не VERIFIED
- READY: зависимости верифицированы и владение доступно
- IN-FLIGHT: запущен, ещё не верифицирован независимо
- VERIFIED: реверификация родителя пройдена, ручные гейты проверены
- ABANDONED: хотя бы один требуемый гейт имеет записанную передачу; не является полным завершением

Состояние ветки - ровно одно из OPEN, VERIFIED, ABANDONED. Реестры листьев хранятся как `gates/leaf-<id>.md`, интеграционные реестры - как `gates/node-<id>.md`. Веточный путь не помечается как `leaf-*`.

## Цикл драйвера

1. **План до fan-out.** Перечитай исходный запрос и правки. Создай `.agents/.tmp/unlazy/<scope>/PLAN.md`, `.agents/.tmp/unlazy/<scope>/GATES.md` и по реестру на каждый лист и ветку из шаблонов. Занеси в реестр контракта каждый независимо опустимый исход и каждое приёмочно значимое ограничение со стабильным идентификатором, владельцем, наблюдающим гейтом или ревью, диспозицией и ревизией. Зафиксируй интерфейсы, именование, цепочку инструментов, зависимости и точное владение до запуска.
2. **Просмотр и одобрение проверок.** Прогони `gate-check --status` по каждому унаследованному реестру. Просмотри каждый `CHECK:`, `EXPECT:`, `CWD:`, включая вызываемые скрипты. Определи shell и унаследованный PATH; новый оракул без точного одобрения печатает свои значения при обычном прогоне без исполнения. `--approve` - только после просмотра; при существующем одобрении обычный прогон не является сухим.
3. **Claim каждого параллельного листа.** Выполни:

   ```text
   node <skill-dir>/scripts/gate-check.mjs --scope <scope> --leaf leaf-1.2.1 --claim
   ```

   Отказ в claim означает, что разбиение небезопасно для параллельного запуска: поменяй план или исполняй последовательно; обход отказа запрещён.
4. **Запуск каждой готовой волны.** Каждому листу - только общий контракт, его точное владение и зависимости, его реестр и правило четырёх проходов. Для независимых листьев READY: открыть волну, запустить всех нативных агентов, записать хэндлы, seal до первого ожидания. Подробности - в `references/dispatch.md`; истории несвязанных листьев не протекают.
5. **Независимая верификация возврата.** Запиши нативный возврат в его волну, затем повторно исполни исполняемые гейты вернувшегося листа, включая уже закрытые:

   ```text
   node <skill-dir>/scripts/gate-check.mjs --root . --cwd . --reverify .agents/.tmp/unlazy/<scope>/gates/leaf-1.2.1.md
   ```

   Один `--status` - не реверификация. Если одобренный оракул изменился, просмотри и одобри новый оракул до продолжения. Ручные гейты проверь напрямую; попробуй опровергнуть хотя бы один пройденный гейт.
6. **Запись статуса и роллинг.** Дополни журнал без переписывания истории:

   ```text
   node <skill-dir>/scripts/gate-check.mjs --scope <scope> --log "leaf-1.2.1 verified"
   ```

   Пометь лист VERIFIED, освободи lease именно этого листа и запиши освобождение до повышения:

   ```text
   node <skill-dir>/scripts/gate-check.mjs --scope <scope> --leaf leaf-1.2.1 --release
   node <skill-dir>/scripts/gate-check.mjs --scope <scope> --log "leaf-1.2.1 lease released"
   ```

   Только после этого переводи разблокированные листья из WAITING в READY и запускай их, не ожидая несвязанных листьев в полёте.
7. **Интеграция снизу вверх.** Реестр `node-*.md` обрабатывается после возврата всех названных детей: реверификация детей, затем интерфейсы, сквозное поведение, регрессии.
8. **Сверка, освобождение, отчёт.** Перечитай исходный запрос и просмотри каждую актуальную строку реестра контракта. Отсутствующее или устаревшее владение и наблюдение, отказ, отсрочка и решение владельца - не завершение. Весь скоуп освобождается только после того, как все листья завершены, все волны терминальны, веточные и корневой реестры реверифицированы и финальная агрегатная верификация выполнена. Скоуп-освобождение до этого момента - только явное восстановление после проверки, что записанный владелец исчез. Отчитывайся, когда закрыты и реестр контракта, и корневой реестр; каждое сообщённое число перемерь.

## Конкурентность проверок

Проверки гейтов идут последовательно (`--jobs 1`) - самый простой для отладки транскрипт. `--jobs <N>` - только для независимых исполняемых гейтов, когда параллельное исполнение сокращает время:

```text
node <skill-dir>/scripts/gate-check.mjs --root . --cwd . --reverify --jobs 4 .agents/.tmp/unlazy/<scope>/gates/leaf-1.1.1.md .agents/.tmp/unlazy/<scope>/gates/leaf-1.1.2.md
```

Лимит скользящий: новая проверка стартует по завершении предыдущей, без ожидания фиксированной партии. Вывод и обновления файла детерминированы в порядке реестра. `--jobs` управляет исполнением команд, не диспетчеризацией агентов и не готовностью зависимостей; для параллелизма агентов - волны из `references/dispatch.md`.

## Роллинг-диспетчеризация

Обращайся с диспетчеризацией как с циклом:

```text
while an unverified leaf remains:
  collect the independent READY leaves up to the host concurrency limit
  open a dispatch wave for that exact set
  launch every native agent and record every returned host handle
  seal the wave before the first wait
  wait for the next leaf to return
  record that return in its dispatch wave
  reverify that leaf and review its manual evidence
  append status and mark it VERIFIED
  release that exact leaf lease and record the release
  promote each WAITING leaf whose Needs are all VERIFIED
```

Зависимость не изобретается во время диспетчеризации: она вносится в PLAN.md, состояния корректируются, изменение записывается. Правка пользователя увеличивает ревизию контракта и сверяется до нового зачёта завершения. Предпочитай независимые листья, но не форсируй независимость там, где интерфейс должен быть установлен первым.

## Иерархия верификации

1. **Самопроверка листа** - ловит обычную неполноту, но остаётся само-сертификацией.
2. **Реверификация родителя `--reverify`** - исполняет каждый исполняемый оракул заново вместо доверия старым или рукописным доказательствам.
3. **Интеграция ветки** - ловит локально корректных детей, которые не собираются вместе.
4. **Опциональный Stop-хук** - не даёт драйверу завершиться при незакрытых реестрах или незавершённых волнах; проверок не исполняет и их смысл не проверяет.

Родитель использует ту же требуемую цепочку инструментов и заявленную shell. Расхождение окружения записывается и разрешается, а не закрывается старым доказательством.

## Ручные гейты

Автоматизация доказывает не всё. Для каждого ручного гейта:

- цитируй точный артефакт, место, измерение или решение ревьюера
- ревьюй последствия, а не только внешнюю полировку
- для высокорисковых исходов получай независимое ревью, когда возможно
- при неоднозначном доказательстве гейт остаётся незакрытым

Лист не называется VERIFIED только потому, что все исполняемые гейты прошли.

## Когда не оркестрировать

Оставайся в solo, когда один сфокусированный контекст реализует и проверяет задачу без скрытия независимых результатов. У оркестрации есть накладные расходы планирования и интеграции; её назначение - изоляция внимания, а не церемония.
