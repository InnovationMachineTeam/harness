# Эксплуатация: процессы, промпты, настройки, папки

## Процессы

Вкладка "Процессы" пространства рантайма: `ps axo pid,ppid,etime,pcpu,pmem,command`, отфильтрованный паттерном адаптера; тип `app` (путь содержит `.app/`) или `cli`.

Действия (`POST /api/processes/action`):

- **стоп** - SIGTERM → до 3 с грации → SIGKILL. Перед сигналом PID перепроверяется свежим срезом ps (защита от переиспользованных PID);
- **рестарт** - только для `app`: остановка + `open -a <ИмяПриложения>`. CLI-процессы перезапускать нельзя - их запускает пользователь.

## Промпты и "Исправить"

`POST /api/prompts/run {prompt | issue}` запускает промт в **новой** headless-сессии рантайма; процесс отвязанный (detached), вывод - в `.agents/console/runs/<ts>-<runtime>.log` (каталог в .gitignore), сессия появляется в общем списке.

Какой рантайм исполняет:

```
явный runtime в запросе → settings.taskRuntimes.promptExecution → defaultRuntime (★)
```

Кнопка **"Исправить"** во вкладке "Диагностика" формирует промпт по проблеме (`core/prompts.ts#buildFixPrompt`: заголовок, детали, рекомендация + требования соблюдать AGENTS.md/guard) и идёт через этот же роут. Если эффективный рантайм не выбран - кнопка заблокирована с подсказкой.

Безопасность: промт санитизируется (NUL, длина 32 КБ, ведущий `-`); спавн - литеральные команды и массивы аргументов, без оболочки; логи - в игнорируемом каталоге.

## Настройки: рантайм под задачу

Страница "Настройки": для задач "Исполнение команд" и "Создание навыка" выбирается рантайм или "По умолчанию" (= ★, звезда на карточке/в space). Разрешены только рантаймы, известные harness. Хранится в `state.settings.taskRuntimes` (null = "по умолчанию"); клиентский стор обновляется после записи файла.

## Рабочие папки

`/workspaces`: ровно одна **обязательная** папка (по умолчанию - корень репозитория; заменить можно, удалить - нет) + дополнительные - по умолчанию `docs/` и `sources/`. Валидация: абсолютный путь, существует, без дублей. Назначение - фильтрация сессий ([sessions.md](sessions.md)) и масштаб repo-сигналов активности.

**`sources/` - локальная работа с проектами**: каталог для клонов репозиториев, над которыми ведётся работа (в git не попадает - игнорируется). Кнопка "Клонировать репозиторий": https-ссылка → `git clone` в `sources/<имя>` (job с терминалом; https-only, хосты не из приватных сетей).

Тогглы **OpenWiki**/"Graphify" в каждой строке включают папку в сборку вики и графа (`state.workspaces.openwiki` / `.graphify`); убранная из списка папка автоматически снимается с них.

## Память (Memory)

`/memory` - вкладка "Память": документы рабочих папок, вики OpenWiki и memory-файлы рантаймов. Всё читается с диска, собственных хранилищ нет. Тот же перечень файлов - во вкладке "Память" внутри каждого рантайма (`/runtime/<id>`), в разрезе одного рантайма.

### Docs

Все markdown-файлы рабочих папок в глубину (скрытые каталоги, `node_modules`, `.git` пропускаются; лимиты: 500 файлов, глубина 8). Навигация - дерево папок слева, справа - рендер (GFM). Автовыбор: README → AGENTS → первый файл.

### OpenWiki

Сборка вики - внешним [openwiki CLI](https://github.com/langchain-ai/openwiki): `npm install -g openwiki` (Node ≥ 22, LLM-ключ настраивается при первом запуске CLI; ставится и скриптом `bun run setup` - см. AGENTS.md §10). Вики ведётся **на русском языке**: сборка выполняется `openwiki --language ru --init|--update "Веди вики на русском языке."`. Для папок, включённых тогглом в "Рабочих папках", кнопки **Собрать** (`openwiki --init`, если `openwiki/index.md` ещё нет) и **Обновить** (`openwiki --update`). Сборка идёт отвязанным процессом; статус опрашивается раз в 4 с, хвост лога виден в навигации:

- `openwiki/.console-build.json` - pid/режим/время старта (пишет консоль);
- `openwiki/.console-build.log` - вывод сборки;
- `openwiki/.last-update.json` - отметка генерации (пишет сам openwiki).

Вики хранится в `<папка>/openwiki/` и версионируется вместе с проектом.

### Graphify

Тоггл **Graphify** в "Рабочих папках" включает папку в сборку графа знаний (`state.workspaces.graphify`). Сборка - внешним [graphify CLI](https://github.com/safishamsi/graphify) (`uv tool install graphifyy`, ставится и скриптом `bun run setup`): кнопка **Собрать** (`graphify extract .` при первом запуске) / **Обновить** (`graphify update .`) запускает отвязанный процесс (мета - `graphify-out/.console-build.json`, лог - `.console-build.log`, статус опрашивается раз в 4 с). Кнопка **Опубликовать** копирует `graphify-out/graph.html` в `public/graphify/<slug>/index.html` - граф встраивается iframe с того же origin; vis-network грузится с unpkg (просмотр - интернет, сборка локальная). Управление CLI и per-runtime интеграциями - "Настройки → Инструменты" ([tools.md](tools.md)).

### Визуализатор (граф вики)

Кнопка **"Граф"** у собранной папки встраивает статический визуализатор openwiki прямо во вкладку. Консоль выполняет `openwiki visualize openwiki --export <dir>/openwiki/.visualizer` - чисто локальная и мгновенная генерация (без LLM): 5 файлов (`index.html`, `client.js`, `client-lib.js`, `styles.css`, `graph.json`) публикуются в `apps/console/public/visualizers/<slug>/` и раздаются Next статикой, iframe строит граф с того же origin.

- Если вики обновилась после экспорта - чип "устарел"; кнопка **"Обновить"** перегенерирует граф (мгновенно).
- Сами библиотеки графа (force-graph, marked, DOMPurify, mermaid) грузятся с cdn.jsdelivr.net - для **просмотра** графа нужен интернет; генерация работает офлайн.
- Альтернатива на будущее - запущенный сервер `openwiki visualize --no-open` (loopback, live-reload по SSE): он тоже встраивается в iframe (не ставит X-Frame-Options), но требует управления процессом и портом, поэтому консоль использует статический экспорт.

### Runtime

Memory-файлы, которые пишут сами рантаймы, по рабочим папкам + подгруппа "Глобальные":

| Рантайм | Источники |
|---|---|
| claude | `~/.claude/projects/<slug папки>/memory/` + `~/.claude/CLAUDE.md` |
| codex | `~/.codex/memories/` (sqlite-хранилище консолью не читается) |
| zcode, kimi | файловая память не обнаружена (пустое состояние) |
| cursor | память в SQLite (`state.vscdb`) - не читается |
| opencode | файловая память не обнаружена (инструкции - AGENTS.md) |

Группы навигации: заголовок = имя рантайма, линия вниз на всю ширину; внутри - рабочие папки и "Глобальные".

Безопасность чтения - allowlist корней, realpath, запрет скрытых файлов, потолок 1 МБ (см. [architecture.md](architecture.md), раздел "Безопасность").

## Guard-совместимость

- Консоль читает `.agents/runtime/**`, `.mimosa/`, каталоги данных рантаймов; пишет - только в `.agents/console/` и MCP-конфиги по правилу managed-имён ([mcp.md](mcp.md)). Файлы навыков и конфиги `.agents/runtime` не правит.
- Хук Kimi зеркалирован в `~/.kimi-code/config.toml` с безопасной обёрткой (`sh -c 'if [ -f .agents/runtime/guard.mjs ]; then …guard…; else exit 0; fi'`) - в чужих проектах хук молча разрешает вызов.
- `.gitignore` синхронизирован с политикой: секреты (`.env*`, `*.pem`, `id_rsa`, `secrets/`) вне git; состояние консоли - версионируется.
