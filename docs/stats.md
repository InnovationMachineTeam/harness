# Статистика

Event ledger связывает workspace, roadmap item, run, step, attempt, agent, runtime, model, роли и секцию шага. Attempt хранит wall time, статус, runtime, model, роли и usage. Provider receipt ID имеет уникальный индекс и предотвращает двойной учёт.

Runtime output может передать JSON usage с `input_tokens`, `output_tokens` и `cache_tokens`. Harness связывает usage с run и step. Рантаймы с флагом `headlessJson` (claude) вызываются с `--output-format json`: usage и `total_cost_usd` извлекаются из конверта результата; конверт без текста и usage считается ошибкой вызова и уходит в failover рантаймов. Провайдерные кандидаты (`provider:<id>`) получают usage от агентного цикла в процессе воркера. Price card находится в `.agents/providers/<id>/settings.json` и содержит цену input, output и cache за миллион токенов, валюту, источник, дату и verified. Если цена неизвестна, Статистика показывает токены без стоимости. Для смешанного набора показываются известная стоимость и coverage.

Стоимость за период считается в два слоя: зафиксированная стоимость записи (price card рантайма или конверт) плюс оценка по каталогу цен (`.agents/pricing/models.json`, формат - `docs/pricing.md`). Для записи без собственной стоимости берётся эффективная цена модели: официальная цена от официального провайдера, при её отсутствии средняя по провайдерам каталога. Итог - карточка "Токены и стоимость за период" с разбивкой зафиксированная/оценка и покрытием ценой.

Периоды: селектор на вкладке "Статистика" (`1d`, `1w`, `1m`, `3m`, `6m`, `1y`, `all`) действует на таблицы "Сводки" и на heatmap. API `/api/stats?period=<значение>&runtime=<id>` ограничивает выборку снизу по времени (`attempts.started_at`, `usage_receipts.at`, `runs.created_at`) и оставляет записи одного рантайма; ответ содержит блок `totals` (токены, стоимость, покрытие).

Оплата рантаймов хранится в `settings.billing` (`state.json`): выбор подписки или Pay as You Go на вкладке "Подписки" страницы рантайма, у провайдеров - кнопка-иконка на карточке. Карточка "Оплата рантаймов" показывает выбранные тарифы и суммы пополнений. Подписка и пополнения учитываются отдельно от API-equivalent и не распределяются по задачам.

Privacy наследуется в порядке global, workspace, workflow. `full` сохраняет redacted content, `metadata` сохраняет IDs, размеры, hashes и ссылки на логи, `aggregates` сохраняет агрегаты. Значение по умолчанию - `metadata`. Checkpoints содержат минимальное операционное состояние независимо от analytics privacy.

Вкладка "Статистика" раздела "Мониторинг" (`/monitoring?tab=stats`) содержит под-вкладки "Сводка" и "Heatmap". "Сводка" показывает итоги периода (токены и стоимость), оплату рантаймов, карточку "Расход по дням" (stack-бары, переключатели Модели/Рантаймы и Токены/Стоимость; источник - `usage_receipts` всех workspace-хранилищ, топ-6, остаток в "прочее"; длинные периоды - недельные корзины; API `/api/stats/series?metric=&by=&period=` - `core/statsSeries.ts`), карточку "Инструменты сессий по дням" (ряд вызовов инструментов из индекса сессий; API `/api/stats/tool-series?period=`), карточку "Сессии рантаймов" (число сессий, токены, оценка стоимости, средняя длительность, архетипы длительности, топ проектов с барами, микс инструментов - из индекса сессий `sessions.sqlite`, [sessions.md](sessions.md)), runs, attempts, агрегаты по workflow (прогоны, завершённые, паузы, остановы), вызовы шагов (workflow, шаг, секция, вызовы, токены, стоимость - топ-30), роли, usage и блок AgentPlane: версию CLI, инициализацию workspace, число задач по статусам из `agentplane task list --all` и readiness из preflight. API `/api/stats` возвращает проекцию для выбранной рабочей папки; блок `sessions` - сводка индекса сессий за тот же период. Каждый вызов агента в составе workflow пишет attempt с runtime, моделью, секцией и usage - таблица "Вызовы шагов" собирается из них.

Детализация (drill-down): клик по элементу графика открывает модалку с расшифровкой (API `/api/stats/drill?type=day|model|runtime|tool|project&key=&period=`). День (клик по столбцу графика или кнопка в панели дня heatmap) - задачи дня со ссылками на прогоны, сессии дня, топ моделей дня. Модель и рантайм (клик в легенде "Расхода по дням") - итоги за период, задачи консоли, попытки workflow с ссылками на страницу прогона (workspace-хранилище), сессии индекса. Инструмент (клик в легенде "Инструментов сессий") - сессии с числом вызовов (таблица session_tools индекса, наполняется с момента установки) и дневные счётчики. Проект (клик по бару "Топ проектов") - сессии рабочей папки.

"Heatmap" показывает использование harness по дням (API `/api/stats/heatmap?metric=<значение>&period=<значение>`) с выбором метрики и периода. Метрика `tasks` - заливка дня равна числу задач консоли относительно пикового дня окна; отсчёт - каждая задача из `.agents/console/tasks` (промт рантайму, запрос провайдеру, сборка инструмента, шаг workflow); клик по дню открывает таблицу по инструментам: исполнитель (`runtime:<id>`, `provider:<id>`, `tool:<id>`), запуски, завершено, ошибки, в работе, типы задач. Метрика `sessions` - сессии рантаймов из индекса сессий по дню старта. Метрики `tokens` и `cost` - дневные суммы `usage_receipts` по всем workspace-хранилищам; стоимость - зафиксированная плюс оценка по каталогу цен.
