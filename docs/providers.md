# Провайдеры LLM: реестр, пресеты, проверка, интеграции, статистика токенов

Внутренняя вкладка "Провайдеры" на странице "Рантаймы" ведёт реестр LLM-провайдеров консоли. Реестр дополняет рантаймы: провайдер используется там, где нужен прямой вызов LLM API - задачи "Исполнение команд" и "Создание навыка", диалог вкладки "Агент" (раздел /agent, AI SDK), LLM-настройки OpenWiki и Graphify, экспорт переменных окружения для LangGraph, статистика использования токенов. Исходные модули: `apps/console/src/core/providers.ts` (пресеты, статусы, проверка), `core/providerRun.ts` (запуск промтов), `core/providerAuth.ts` (OAuth-обмен), `core/providerHttp.ts` (транспорт с CA), API - `app/api/providers/route.ts`.

## Пресеты

Реестр содержит фиксированный набор пресетов популярных провайдеров. Над сеткой карточек - два связанных фильтра: по состоянию ("Все", "Не установлены", "Установлены", "Не запущены", "Активны") и по типу ("Cloud", "Local"); фильтры накладываются, счётчики каждого пересчитываются в рамках выбранного значения другого. Пресет задаёт общие настройки (base URL, имя env-переменной для ключа, механизм проверки, схема авторизации) и модель по каждому из четырёх tiers - fast, standard, strong, subagents - тем же составом, что в конфигах рантаймов (`.agents/runtime/<vendor>/config.json`). Значения tiers редактируются в карточке.

| Тип | Пресеты |
|---|---|
| Онлайн | OpenAI, Anthropic Claude, Google Gemini, DeepSeek, Moonshot Kimi, OpenRouter, Groq, xAI Grok, Mistral AI, Together AI, GigaChat (Сбер, OAuth 2.0), YandexGPT (Yandex Cloud) |
| Локально | Ollama, LM Studio, vLLM |

Локальные пресеты не требуют API-ключа; base URL по умолчанию указывает на стандартный порт сервиса (Ollama `http://localhost:11434/v1`, LM Studio `http://localhost:1234/v1`, vLLM `http://localhost:8000/v1`).

У провайдеров с подписками или Pay as You Go в каталоге цен (`.agents/pricing/`, формат в [pricing.md](pricing.md)) на карточке есть кнопка-иконка (CreditCard): окно с radio-выбором тарифа (по умолчанию - "Нет подписки"), пополнениями Pay as You Go и справочными ценами моделей провайдера. Выбор хранится в `settings.billing.providers`.

## Авторизация: статический ключ и OAuth 2.0

Большинство пресетов используют статический ключ: значение из карточки передаётся в заголовке запроса (Bearer, `x-api-key` или query-параметр по механизму проверки). Пресеты с полем `auth.kind = "oauth2"` (GigaChat) работают иначе:

- В поле ключа вставляется ключ авторизации из личного кабинета провайдера (у GigaChat - из GigaChat Studio), а не access-токен.
- Консоль обменивает ключ на короткоживущий access-токен: `POST {auth.tokenUrl}` с заголовками `Authorization: Basic <ключ>` и `RqUID` (UUID) и scope в form-urlencoded теле. Обмен выполняется в `core/providerAuth.ts`, токен кешируется в памяти процесса до истечения (запас 60 секунд); после HTTP 401 кеш сбрасывается и обмен повторяется один раз.
- Scope обмена выбирается в карточке (по умолчанию - `scopeDefault` пресета; у GigaChat: `GIGACHAT_API_PERS` для физлиц, `GIGACHAT_API_B2B` / `GIGACHAT_API_CORP` для платных пакетов).
- Схема задана данными пресета: новый провайдер с OAuth-авторизацией добавляется одним объектом в `PROVIDER_PRESETS`, без кода под конкретного вендора.

Сертификат CA подключается в карточках провайдеров с полем `cert` (GigaChat - обязателен, YandexGPT - опционален): кнопка **Загрузить PEM-файл** выбирает файл из файловой системы, сервер сохраняет его под стандартным именем `ca.pem` в папке провайдера - запросы провайдера всегда читают этот путь (транспорт `core/providerHttp.ts` на `node:https`; глобальный fetch не позволяет подставить CA в отдельный запрос). Это нужно провайдерам с национальными или корпоративными сертификатами: цепочка GigaChat (НУЦ Минцифры) не входит в набор доверенных CA Node - сертификат скачивается на странице НУЦ (gosuslugi.ru/ca); без него запросы к API Сбера не проходят, и карточка показывает красную строку "сертификат не найден". У провайдеров без `cert` поведение не меняется - используется глобальный fetch.

Ограничения OAuth-провайдеров (сторонние потребители получают статический ключ через env и не выполняют обмен):

- OpenWiki и Graphify: провайдер не предлагается в LLM-настройках инструментов (`tools` у пресета не задан).
- Экспорт LangGraph: кнопка скрыта, действие возвращает ошибку с причиной.

## Файлы настроек провайдеров

Изменяемые настройки каждого провайдера - файлы в `.agents/providers/<id>/` (модуль `core/providerSettings.ts`):

| Файл | Содержимое | Git |
|---|---|---|
| `settings.json` | base URL, модели tiers, scope обмена (OAuth) | включён |
| `key.env` | ключ доступа одной строкой `<ENV>=<значение>` (ENV - из пресета) | исключён |
| `ca.pem` | сертификат CA, загруженный файлом под стандартным именем | исключён |

Правила:

- `settings.json` версионируется (настройки можно переносить коммитом); `key.env`, `*.pem` и прочие файлы ключей/сертификатов исключены в `.gitignore`.
- Результат проверки (`verifiedAt`, `verifyError`, `verifyModels`) - машинное состояние в `.agents/console/state.json`; изменение любого файла настроек или сертификата сбрасывает проверку.
- Запись для UI и запросов собирается из файлов и результата проверки (`readProviderEntry`); недостающие значения берутся из пресета.
- Записи старого формата (все поля в state.json) переносятся в файлы автоматически при первом запросе (`migrateProviderEntries` в server-context).
- Кнопка **Очистить** удаляет все три файла и результат проверки.

## Статусы: заполнение, проверка, активация

| Статус | Условие | Карточка |
|---|---|---|
| `not-installed` | Локальный пресет, бинарник не найден (PATH и известные пути) | Выглядит отключенной, бейдж "не установлен" |
| `not-running` | Локальный сервис установлен, но endpoint не отвечает | Бейдж "не запущен", кнопка проверки недоступна |
| `empty` | Не все поля заполнены (ключ, base URL, хотя бы один tier пуст) | Выглядит отключенной: пунктирная рамка, приглушённые тона |
| `filled` | Все поля заполнены, проверка не проводилась | Кнопка **Проверка** |
| `error` | Последняя проверка не пройдена | Текст ошибки, кнопка **Проверка** |
| `active` | Проверка пройдена (`verifiedAt` записан) и ключ заполнен | Бейдж "активен", доступны интеграции |

Правила:

- Базовые настройки каждого пресета существуют как файл `.agents/providers/<id>/settings.json` (создаётся при первом запросе консоли с базовыми значениями пресета; пользовательские файлы не перезаписываются) - карточки подставляют значения из этих файлов.
- Провайдер активен только после успешной проверки и при заполненном ключе; провайдер без ключа (key.env пуст или отсутствует) - неактивен, независимо от прошлой проверки. Локальные пресеты без требования ключа активируются проверкой.
- Для локальных пресетов состояние сервиса приоритетнее заполнения: карточка показывает чипы "установлен/не установлен" и "запущен/не запущен"; проверка запускается только при работающем сервисе. Установка - `existsSync` бинарника в каталогах PATH и известных путях пресета (`core/providerLocal.ts`, без запуска процессов); запуск - один запрос к endpoint с таймаутом 1.5 с.
- Изменение любого файла настроек (ключ, base URL, модели, scope, сертификат) сбрасывает результат проверки - провайдер возвращается в `filled`.
- Проверка - лёгкий GET списка моделей по механизму пресета: OpenAI-совместимый (`GET {baseUrl}/models`, Bearer-ключ), Anthropic (`x-api-key` + `anthropic-version`), Gemini (`?key=`). Ответ парсится, найденные идентификаторы моделей (до 20) показываются в карточке как подсказка для tiers. Для OAuth-провайдеров проверка сначала выполняет обмен ключа на токен; ошибка обмена показывается как текст проверки.
- Кнопка **Очистить** (с подтверждением) удаляет файлы провайдера и статус проверки; базовый settings.json восстанавливается при следующем запросе.

## Безопасность

- Ключи хранятся в `.agents/providers/<id>/key.env` (вне git), в UI вводятся как password-поля; сертификаты - `ca.pem` рядом (вне git). `settings.json` секретов не содержит и версионируется.
- Base URL валидируется (`providerBaseUrlError`): только протоколы http/https, userinfo (`user:pass@`) запрещён, облачный metadata-хост `169.254.169.254` запрещён. Для онлайн-пресетов локальные/приватные/зарезервированные адреса запрещены (`onlineHostError`: loopback, `10/8`, `172.16/12`, `192.168/16`, link-local, multicast/reserved, IPv6 ULA/link-local); loopback разрешён только локальным пресетам - в этом их назначение.
- Серверный транспорт `providerHttp` проверяет протокол и хост каждого URL до соединения (та же политика), подставляет CA только в запросы своего провайдера.
- Запросы выполняются в процессе консоли (без дочерних процессов и оболочки); таймаут запуска промта - 5 минут, проверка и обмен токена - 10 секунд. Загружаемый сертификат ограничен 64 КБ и проверяется на блок BEGIN CERTIFICATE.

## Интеграции

| Интеграция | Как включается | Что даёт |
|---|---|---|
| OpenWiki | "Настройки - Основные", панель "OpenWiki (сборка вики)": выбрать провайдера. Та же привязка - шестерёнкой в "Инструментах" | В `state.openwikiLlm` выводятся пресет, ключ, base URL и модель (standard) из записи провайдера и пишется `providerId` - карточка показывает чип "OpenWiki" |
| Graphify | "Настройки - Основные", панель "Graphify (сборка графа)": выбрать провайдера. Та же привязка - шестерёнкой в "Инструментах" | В `state.graphifyLlm` выводятся пресет и ключ провайдера, пишется `providerId` - чип "Graphify" |
| LangGraph | Кнопка **Экспорт для LangGraph** на карточке (только у активного) | Файл `.agents/console/langgraph.env`: `LANGGRAPH_PROVIDER`, ключ под родной env-переменной пресета (и дублем `OPENAI_API_KEY` для OpenAI-совместимых), `OPENAI_BASE_URL`, `LANGGRAPH_MODEL_FAST|STANDARD|STRONG|SUBAGENTS` |
| Задачи консоли | "Настройки - Основные": в селекторах "Исполнение команд" и "Создание навыка" активные провайдеры предложены рядом с рантаймами | Значение `provider:<id>` в `state.settings.taskRuntimes`; промт уходит в API провайдера (модель tier `standard`), ответ - в `.agents/console/runs/<ts>-provider-<id>.log` |
| Агент (AI SDK) | Звезда ★ на карточке активного провайдера или панель "AI SDK" в "Настройки - Основные" (там же - кнопка установки пресета) | `state.defaultProvider`; раздел /agent ведёт с провайдером стриминговый диалог (`POST /api/agent/chat`: LangGraph-граф `core/agent/chatGraph.ts` + LangChain-модель `core/langchain/chatModel.ts` по kind пресета, модель выбранного tier, effort → `reasoning_effort`). Выбор исполнителя на вкладке "Агент" сохраняется в `state.settings.agentExecutor` и восстанавливается при загрузке; в модель уходит хвост истории - последние N реплик (`state.settings.agentHistoryLimit`, по умолчанию 20, 0 - все). Без выбора действует Ollama (`FALLBACK_PROVIDER_ID`) |

"Настройки - Основные" показывает все кейсы использования провайдеров: две задачи консоли и два инструмента памяти. В селекторах инструментов предложены только проверенные провайдеры, у которых есть маппинг на пресеты этого инструмента (`tools.openwiki` / `tools.graphify` в пресете, значения - id из `core/llmPresets.ts`); значение "Вручную" оставляет поля в настройках инструментов. PUT LLM-роутов инструмента с `providerId` (без полей) выводит поля из записи активного провайдера на сервере.

## Статистика использования токенов

Хранилище - файл `.agents/console/provider-usage.json` (модуль `core/providerUsage.ts`): записи-хвост (до 2000), инкрементальные итоги `totals` по провайдеру и модели, счётчики `days` по дням (90 дней), позиции обработки файлов `cursors` и кумулятивные счётчики для дельт. Запись файла атомарная (tmp + rename). Карточки провайдеров показывают "токены за 30 дней - вызовов всего"; сводная строка - над сеткой карточек.

Источники записей (`source` в записи):

| Источник | Что собирает | Как |
|---|---|---|
| `provider-run` | Прямые вызовы консоли (задачи "Исполнение команд", "Создание навыка" со значением `provider:<id>`): usage из ответа API по механизму пресета | `core/providerRun.ts` пишет в момент выполнения |
| `agent-chat` | Диалог вкладки "Агент" (`POST /api/agent/chat`, провайдер): usage из `streamText` | маршрут пишет после завершения стрима |
| `runtime-session` | Сессии рантаймов: Claude Code (per-message usage, `~/.claude/projects/*/*.jsonl`), ZCode (per-request usage, `~/.zcode/cli/rollout/model-io-*.jsonl`), Codex (кумулятивные `token_count`, дельта от прошлого сбора) | `core/usage/runtimeTranscripts.ts`, инкремент по позиции файла; синтетические записи и дубли пропускаются |
| `tool-ledger` | Счётчики инструментов: graphify (`graphify-out/.graphify_cost.json` корня и хранилища `graphify/*/graphify-out/`, дельта итогов), headroom (события сжатия `~/.headroom/savings_events.jsonl`, saved-токены по модели) | `core/usage/toolLedgers.ts`; rtk не учитывается - это сжатие shell-вывода, не LLM-токены (см. tools-usage.json) |

Атрибуция провайдера - по имени модели: точное совпадение с моделями пресетов (id провайдера), затем с моделями конфигов рантаймов (`runtime:<vendor>`); без совпадения - `runtime:<id>` рантайма или имя инструмента. Сбор внешних источников (`runtime-session`, `tool-ledger`) запускается лениво при запросе `GET /api/providers/usage`, не чаще раза в 5 минут; вызовы консоли пишутся сразу.

Потребление внешними инструментами: JSON `GET /api/providers/usage` (`{records, totals, days, collectedAt}`) или файл `.agents/console/provider-usage.json` напрямую.

## API

| Маршрут | Назначение |
|---|---|
| `GET /api/providers` | Реестр: пресеты, собранные записи (файлы + проверка), статусы, интеграции, назначенные задачи |
| `PUT /api/providers` | Сохранить настройки `{id, apiKey, baseUrl, models, authScope?}` в `.agents/providers/<id>/` (settings.json + key.env); изменение сбрасывает проверку |
| `POST /api/providers {action:"verify"}` | Проверить соединение (для OAuth-провайдеров - с обменом токена); успех записывает `verifiedAt` |
| `POST /api/providers {action:"upload-cert", content}` | Сохранить PEM-сертификат под стандартным именем `ca.pem` (провайдеры с полем `cert`) |
| `POST /api/providers {action:"remove-cert"}` | Удалить сертификат провайдера |
| `POST /api/providers {action:"export-langgraph"}` | Записать `.agents/console/langgraph.env` (только активному со статическим ключом) |
| `POST /api/providers {action:"clear"}` | Удалить файлы настроек провайдера и результат проверки |
| `GET /api/providers/usage` | Статистика токенов: записи-хвост (200), итоги по провайдерам и моделям, счётчики по дням |

`PUT /api/settings` принимает значения задач вида `provider:<id>` (только активные провайдеры) и `defaultProvider` (провайдер AI SDK по умолчанию для вкладки "Агент", null - Ollama); `POST /api/prompts/run` и `POST /api/skills/create` маршрутизируют значения задач в `core/providerRun.ts`.
